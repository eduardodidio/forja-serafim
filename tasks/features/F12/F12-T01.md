## User Story

Como administrador, quero que uploads de arquivos sejam gravados de forma segura
(sem race conditions), slugs validados, falhas de gravacao tratadas sem arquivos
orfaos, e erros de processamento de imagem reportados no frontend.

## Dev Notes

### 1. Await `Bun.write()` — 3 locais em `admin/src/server.ts`

`Bun.write()` retorna uma Promise. Sem `await`, o codigo continua antes do arquivo
estar gravado no disco. Isso causa race condition especialmente na linha 482 onde
`processImage(tmpPath, ...)` le o arquivo imediatamente apos.

**Locais:**

- Linha ~345: cover upload → `await Bun.write(dest, buffer);`
- Linha ~362: manual PDF upload → `await Bun.write(dest, buffer);`
- Linha ~482: sample image upload → `await Bun.write(tmpPath, buffer);`

### 2. PDF upload — validar MIME type alem da extensao

Linha ~356-357: atualmente so checa `.endsWith(".pdf")`.
Adicionar validacao de `file.type`:

```ts
const isPdf =
  file.name.toLowerCase().endsWith(".pdf") && (file.type === "application/pdf" || file.type === "");
if (!isPdf) return json({ error: "Arquivo deve ser PDF." }, 400, req);
```

Nota: `file.type` pode ser vazio em alguns browsers, entao aceitar "" como fallback.

### 3. Slug sanitization nas rotas de API

Validar que slugs extraidos de URL match `/^[a-z0-9]+(?:-[a-z0-9]+)*$/` antes de usar
em operacoes de arquivo. Aplicar em:

- `coverMatch[1]` (linha ~332)
- `manualMatch[1]` (linha ~352)
- `samplesMatch[1]` (linha ~430 area)
- Qualquer outro `path.match` que extrai slug

Criar helper:

```ts
function isValidSlug(s: string): boolean {
  return /^[a-z0-9]+(?:-[a-z0-9]+)*$/.test(s);
}
```

### 4. writeJson — try-catch no renameSync (`admin/src/lib/data-io.ts`)

Se `renameSync` falha (disco cheio, permissao), o arquivo tmp fica orfao.
Adicionar try-catch com cleanup:

```ts
export function writeJson(path: string, data: unknown): void {
  const dir = dirname(path);
  const tmp = join(dir, `.tmp-${randomBytes(6).toString("hex")}.json`);
  writeFileSync(tmp, JSON.stringify(data, null, 2) + "\n", "utf-8");
  try {
    renameSync(tmp, path);
  } catch (err) {
    try {
      unlinkSync(tmp);
    } catch {
      /* best-effort cleanup */
    }
    throw err; // re-throw para o caller saber
  }
}
```

### 5. Image processing — reportar erros parciais (`admin/src/server.ts`)

Atualmente erros de `processImage` sao logados mas o frontend
recebe `{ processed: [...] }` sem saber quais falharam.

Adicionar array `failed` na resposta:

```ts
const failed: Array<{ file: string; error: string }> = [];

// No catch:
catch (err) {
  console.error(`Failed to process ${file.name}:`, err);
  failed.push({ file: file.name, error: String(err) });
}

// Na resposta:
return json({ processed, failed }, 200, req);
```
