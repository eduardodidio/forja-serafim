# F17-T02: Token image storage + watermark processing

**Feature:** F17
**Wave:** 0
**Type:** backend
**Depends on:** none
**Status:** done

## User Story

As the system, I need token images to be watermarked and stored in a dedicated directory so that art is protected and tokens are organized separately from deck cards.

## Objective

Create the token image storage directory structure and ensure the existing image processing pipeline handles tokens correctly.

## Dev Notes

### 1. Directory structure

Create directories (server should mkdir -p on startup or on first upload):
```
public/images/tokens/{slug}/
```

### 2. Paths constant — `admin/src/lib/paths.ts`

Add:
```typescript
export const TOKENS_DIR = path.join(PROJECT_ROOT, "public", "images", "tokens");
```

### 3. Image processing — `admin/src/lib/image-processor.ts`

The existing `processImage(input, outputPath)` already:
- Resizes to max 600px width
- Applies "Forja Serafim" watermark (5 diagonal lines, 40% opacity)
- Outputs JPEG at 80% quality

**No changes needed** to `image-processor.ts` — tokens reuse the same function.
The T01 endpoint code will call `processImage(buffer, tokenOutputPath)` with the token-specific output path.

### 4. Ensure directory creation

In the POST `/api/collections/:slug/tokens` handler (from T01), before writing files:
```typescript
import { mkdirSync } from "fs";
mkdirSync(path.join(TOKENS_DIR, slug), { recursive: true });
```

This follows the same pattern as sampleImages upload (server.ts ~line 580).

### 5. Static serving

Verify that `public/images/tokens/` is served by the static file server. The admin server already serves `public/` as static root, so `/images/tokens/` should work automatically.

For the landing page (Vite), files in `public/` are served at root — `/images/tokens/` will work in dev and build.

### Key files:
- `admin/src/lib/paths.ts` — add TOKENS_DIR
- `admin/src/lib/image-processor.ts` — no changes, reuse processImage()
- `admin/src/server.ts` — mkdirSync in token upload handler
- `public/images/tokens/` — new directory (gitkeep)

## Testing

- **Happy path:** Token image processed at 600px max width with watermark
- **Edge case:** Very small image (< 600px) should not be upscaled
- **Edge case:** PNG with transparency converted to JPEG properly
- **Boundary:** Token directory created on first upload for a slug
