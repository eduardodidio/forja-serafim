# F17-T01: Extend data model + backend endpoints for tokens

**Feature:** F17
**Wave:** 0
**Type:** backend
**Depends on:** none
**Status:** done

## User Story

As the admin, I want backend endpoints to manage tokens (upload, delete, reorder) so that I can maintain which tokens accompany each deck.

## Objective

Extend the Collection type with a `tokens` array and add CRUD endpoints mirroring the sampleImages pattern.

## Dev Notes

### 1. Data model — `src/lib/store-data.ts`

Add to the `Collection` type:

```typescript
export type Token = {
  image: string; // "/images/tokens/{slug}/{name}.jpg"
  name: string; // display name
  quantity: number; // how many of this token
};

export type Collection = {
  // ... existing fields ...
  tokens: Token[];
};
```

### 2. collections.json — `src/data/collections.json`

Add `"tokens": []` to each existing collection object.

### 3. Server endpoints — `admin/src/server.ts`

Mirror the sampleImages endpoints pattern:

**POST `/api/collections/:slug/tokens`** (multipart)

- Accept FormData with `files` (images) + `names` (JSON array of names) + `quantities` (JSON array of numbers)
- Validate slug, file types (JPEG/PNG/WebP), quantities > 0
- Process each image with `processImage()` (watermark) — save to `public/images/tokens/{slug}/{safeName}.jpg`
- Return `{ processed: [{ image, name, quantity }], failed: [] }`
- Call `gitPersist("Upload tokens: {slug}")`

**DELETE `/api/collections/:slug/tokens/:filename`**

- Remove token from collection's `tokens` array
- Delete physical file from `public/images/tokens/{slug}/{filename}`
- Write collections.json
- Call `gitPersist("Remover token: {slug}/{filename}")`

**PUT `/api/collections/:slug/tokens/reorder`**

- Accept `{ tokens: Token[] }` body
- Validate all images exist in current collection
- Replace tokens array
- Write collections.json
- Call `gitPersist("Reordenar tokens: {slug}")`

### 4. gitPersist paths — `admin/src/lib/git-persist.ts`

Add `public/images/tokens/` to the staged paths array (alongside `public/images/decks/`).

### Key files:

### Conventions:

- Slug validation: `/^[a-z0-9-]+$/`
- Path traversal prevention: filename must not contain `..`, `/`, `\`
- Use `execFileSync` not `execSync` for git commands (existing pattern)
- Serial queue via gitPersist (no concurrent git ops)

## Testing

- **Happy path:** Upload 2 tokens with quantities, verify response and file creation
- **Edge case:** Upload token with quantity=0 should be rejected
- **Edge case:** Upload to collection with no tokens array yet
- **Error scenario:** Invalid file type rejected with 400
- **Boundary:** Token filename sanitization (unicode, special chars)

## Acceptance criteria

- [ ] Collection type includes `tokens: Token[]`
- [ ] Existing collections.json has `"tokens": []` for each collection
- [ ] POST endpoint creates watermarked token images in `/images/tokens/{slug}/`
- [ ] DELETE endpoint removes token + physical file
- [ ] PUT reorder endpoint reorders tokens array
- [ ] gitPersist stages `public/images/tokens/` directory
- [ ] All endpoints call gitPersist after mutation
