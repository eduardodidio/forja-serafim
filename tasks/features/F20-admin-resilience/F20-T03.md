# F20-T03 — Fix Stale State After Delete/Re-Insert

**Wave:** 1
**Status:** done
**File:** `admin/public/index.html`

## User Story

As an admin, I want to delete a token and immediately re-insert a new one without
needing a full page refresh, so that my editing workflow is smooth and reliable.

## Dev Notes

**File:** `admin/public/index.html`

### Problem Analysis

After `loadCollections()`, the server returns token image paths with `?v=<mtime>`
cache-bust suffixes (e.g., `/images/tokens/castlevania/alucard.jpg?v=1700000000`).
The UI functions extract the filename using `token.image.split("/").pop()`, which
yields `alucard.jpg?v=1700000000` instead of `alucard.jpg`. When this filename is
passed to `removeToken(slug, filename)` or `updateTokenQuantity(slug, filename, qty)`,
the constructed `imagePath` becomes `/images/tokens/castlevania/alucard.jpg?v=1700000000`
which does NOT match the server-returned `token.image` (which may have a different `?v=`
value after a reload).

### Fixes Required

1. **`removeToken` function (line ~2025):**
   - Line 2029: Strip query string from filename before constructing imagePath:
     ```js
     const cleanFilename = filename.split("?")[0];
     const imagePath = `/images/tokens/${slug}/${cleanFilename}`;
     ```
   - Line 2030: Compare without query strings:
     ```js
     const idx = c.tokens.findIndex((t) => t.image.split("?")[0] === imagePath);
     ```
   - Line 2038: Use `cleanFilename` in the DELETE API call:
     ```js
     const res = await apiFetch(`${API}/api/collections/${slug}/tokens/${cleanFilename}`, { ... });
     ```

2. **`updateTokenQuantity` function (line ~2081):**
   - Line 2086: Same fix — strip query string:
     ```js
     const cleanFilename = filename.split("?")[0];
     const imagePath = `/images/tokens/${slug}/${cleanFilename}`;
     ```
   - Line 2087: Compare without query strings:
     ```js
     const token = c.tokens.find((t) => t.image.split("?")[0] === imagePath);
     ```

3. **`updateEditTokensGrid` function (line ~2155):**
   - Line 2178: The `onchange` handler extracts filename with `.pop()` which includes `?v=`.
     Strip it in the inline handler:
     ```js
     onchange="updateTokenQuantity('${esc(slug)}', '${esc(token.image.split("/").pop().split("?")[0])}', parseInt(this.value))"
     ```
   - Line 2182: Same for the `removeToken` onclick:
     ```js
     onclick="removeToken('${esc(slug)}', '${esc(token.image.split("/").pop().split("?")[0])}')"
     ```

4. **`uploadEditTokens` function (line ~2109):**
   - Line 2147: After `input.value = ""`, this already resets the file input.
     Verify this is sufficient. If the browser caches the old value, force reset:
     ```js
     input.value = "";
     input.type = "";
     input.type = "file"; // force reset for same-file re-upload
     ```

5. **`moveToken` function (line ~2053):**
   - The reorder endpoint receives full token objects including `image` paths.
     No filename extraction needed here, so no fix required. However, verify
     the tokens sent to the server match what the server expects (clean paths
     without `?v=`). If `c.tokens` has `?v=` from loadCollections, the server
     validation at line 762-765 will fail because it compares against persisted
     (clean) paths.
   - Fix: in `moveToken`, strip `?v=` from token images before sending to server:
     ```js
     body: JSON.stringify({
       tokens: c.tokens.map((t) => ({ ...t, image: t.image.split("?")[0] })),
     });
     ```

## Acceptance Criteria

- [ ] `removeToken` correctly finds and deletes tokens regardless of `?v=` cache-bust
- [ ] `updateTokenQuantity` correctly finds tokens regardless of `?v=` cache-bust
- [ ] After deleting a token, re-uploading a new token works without page refresh
- [ ] File input is properly reset after upload (same file can be re-uploaded)
- [ ] `moveToken` sends clean image paths to the reorder endpoint
- [ ] No JS console errors during delete -> re-insert workflow
