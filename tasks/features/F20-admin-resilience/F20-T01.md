**Wave:** 0

## User Story

As an admin, I want rapid edits to coalesce into a single git commit, so that
the server is not overwhelmed by sequential commit+push cycles that cause 502
timeouts.

## Dev Notes

**File:** `admin/src/lib/git-persist.ts`

Add a new exported function `gitPersistDebounced(description: string): void` that:

1. Maintains module-level state:
   - `debounceTimer: ReturnType<typeof setTimeout> | null = null`
   - `pendingDescription: string | null = null`
   - `const DEBOUNCE_MS = 3000` (3 seconds)

2. On each call:
   - Store `description` in `pendingDescription` (overwriting previous)
   - Clear existing `debounceTimer` if any
   - Set a new `debounceTimer = setTimeout(() => { ... }, DEBOUNCE_MS)`
   - When the timer fires, call `gitPersist(pendingDescription!)` and reset both variables

3. The function is fire-and-forget (returns `void`, not `Promise`). The caller
   does not need to await the result.

4. The existing `gitPersist()` function must remain completely unchanged.
   It is still used for create/delete operations that need immediate persistence.

5. Export `DEBOUNCE_MS` as a named constant for testability.

**Key implementation detail:** The debounce timer resets on every call. If
Anderson changes quantity on 10 tokens in 5 seconds (one every 0.5s), only ONE
gitPersist fires 3 seconds after the last change.
