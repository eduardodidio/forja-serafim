### 4. Component analysis — card-tile.tsx vs colecoes.$slug.tsx

**Listing page (`/colecoes`)** — `card-tile.tsx`:
- Uses `collection.sampleImages` for the flipping card effect.
- Falls back to `[collection.image]` only if `sampleImages` is empty.
- Since all 3 collections have 6 sample images each, the cover (`collection.image`)
  is NEVER shown on the listing page.
- **Conclusion:** If the user saw the wrong cover on the listing page, they were
  actually seeing a sampleImage, not the cover. This rules out hypothesis #6
  from the README (user confusion) for the listing page — the listing page
  simply does not show covers at all.

**Detail page (`/colecoes/$slug`)** — `colecoes.$slug.tsx`:
- Line 73-79: `collection.image` is used directly as the `<img src>` for the
  hero background. This is the only place the cover is rendered.
- The src is a plain path like `/images/covers/castlevania.jpg` with no
  cache-bust parameter.

### 5. Data import chain — static bake confirmed

`src/lib/store-data.ts` imports the JSON statically:
```ts
import collectionsData from "@/data/collections.json";
```

This means the data is **baked into the JS bundle at build time**. Even if the
admin updates `collections.json` on disk, the deployed bundle will still contain
the data from the last `bun run build`. This is the core architecture constraint.

### 6. Hypotheses assessment

| # | Hypothesis | Status |
|---|-----------|--------|
| 1 | Data baked in bundle = stale after admin edit | **CONFIRMED as architectural risk** — but current on-disk data is correct |
| 2 | Slug-image mapping corrupted | **RULED OUT** — JSON on disk and in bundle are both correct |
| 3 | Browser/CDN cache (no cache-bust on front-end) | **PLAUSIBLE** — detail page uses bare path without `?v=mtime` |
| 4 | git-persist failed silently | **NEEDS T02 investigation** |
| 5 | Render serves dist/ over public/ for mutables | **NEEDS T02 investigation** (admin server priority logic) |
| 6 | User saw sampleImage, not cover | **PARTIALLY CONFIRMED** — listing page never shows cover; if user saw wrong image on listing, it was a sampleImage not a cover |

### 7. Key finding

The JSON data and Vite bundle are currently correct. The reported bug
(Castlevania showing cavaleiros-do-zodiaco.jpg) is NOT reproducible from the
current source. This suggests the bug was either:

- (a) **Transient** — caused by a stale bundle on Render that has since been
  redeployed, OR
- (b) **Cache-related** — the browser cached the old image at the same URL path
  before the admin replaced it, and no cache-bust is applied on the front-end.

T02 should investigate the admin server's file-serving priority and git-persist
pipeline to determine if (a) is the root cause.
