## User Story

Como usuario do site, quero que a capa da colecao seja atualizada imediatamente
apos ser alterada no admin, sem precisar limpar cache ou esperar rebuild.

## Dev Notes

### Correcoes Provaveis (aplicar conforme diagnostico da Wave 1)

#### Fix 1 — Cache-bust nas imagens do site

O bundle Vite embute `collections.json` com paths limpos (ex:
`/images/covers/castlevania.jpg`). Sem query string `?v=`, o browser pode
cachear a imagem antiga indefinidamente.

**Opcoes**:

- **A) Build-time cache-bust**: No `vite.config.ts`, usar um plugin que
  adiciona hash ao copiar assets de `public/`. Porem, isso quebraria o path
  no JSON.
- **B) Runtime cache-bust via timestamp**: No componente React, adicionar
  `?v=<build_timestamp>` aos paths de imagem. Pode ser uma variavel
  `import.meta.env.VITE_BUILD_TS` setada no build.
- **C) Service Worker / Cache-Control headers**: Configurar `Cache-Control:
no-cache` para `/images/covers/` no admin server. Mais simples e eficaz.

**Recomendacao**: Opcao C e a mais simples — ajustar o admin server para
servir `/images/covers/*` com `Cache-Control: no-cache, must-revalidate`.
Combinado com opcao B para garantir bust em CDNs.

#### Fix 2 — Mapeamento slug-imagem corrompido

Se T01 revelar que `collections.json` tem o slug errado, corrigir o endpoint
de update/edit que esta salvando o campo `image` incorretamente.

Pontos de atencao:

- `PUT /api/collections` (`server.ts:332`) — verificar se preserva `image`
  ao editar outros campos
- `POST /api/collections/:slug/cover` — ja seta `col.image = /images/covers/${slug}.jpg`
  corretamente, mas verificar se o `slug` do match e o certo

#### Fix 3 — Deploy hook nao acionado

Se T02 revelar que o deploy hook nao e chamado apos git push, adicionar
chamada ao `RENDER_DEPLOY_HOOK` no final do `gitPersist` pipeline.

## Notes from Developer

### Implementation Date: 2026-11-18

### Approach: Build-time cache-bust (Option B from task spec)

Applied a build-time timestamp approach to bust browser/CDN cache for cover and sample images.

### Changes Made

1. **`vite.config.ts`** -- Added `define` block to inject `VITE_BUILD_TS` as a string constant (current `Date.now()` at build time). This gets inlined into the bundle by Vite's define substitution, so there is no runtime overhead.

2. **`src/lib/cache-bust.ts`** (new file) -- Small utility that appends `?v=<BUILD_TS>` to any URL. Returns the URL unchanged if `BUILD_TS` is empty (dev fallback). Handles URLs that already contain query params by using `&` separator.

3. **`src/components/card-tile.tsx`** -- Wrapped `images[displayIdx]` in `cacheBust()` for the card flip image src. This covers both `sampleImages` and the `collection.image` fallback path on the listing page.

4. **`src/routes/colecoes.$slug.tsx`** -- Applied `cacheBust()` in three places:
   - Hero background image (`collection.image`)
   - Lightbox `images` prop (via `bustedSampleImages` array)
   - Sample image grid `<img src>` (via same `bustedSampleImages` array)

### Verification

- `bun run build` succeeds -- bundle includes inlined timestamp (`1795024514179`)
- `bun run lint` clean on all changed files (pre-existing admin lint issues unchanged)
- Confirmed timestamp appears in built JS bundle via grep

### Why NOT Fix 2 or Fix 3

- **Fix 2 (slug-image corruption)**: T01 confirmed `collections.json` on disk has correct mappings. T02 confirmed PUT endpoint never touches the `image` field. No corruption path exists.
- **Fix 3 (deploy hook)**: T02 confirmed git-persist pipeline is correct and includes cover images. Deploy hook is a Render infrastructure concern, not a code bug.

### Architecture Note

Each `bun run build` generates a new timestamp, so every deploy automatically busts all image caches. The persisted JSON on disk remains clean (no `?v=` params) -- cache-bust is applied only at render time in the React components. This is consistent with the serve-time cache-bust pattern already used in the admin API (GET /api/collections).
