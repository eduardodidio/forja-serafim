# F03-T07: Pipeline de otimizacao de imagens

**Wave:** 3 | **Type:** infra | **Status:** planned | **Depends on:** —

## User Story

Como visitante, quero que o site carregue rapido mesmo com muitas imagens de cartas,
para que eu nao desista de navegar.

## Dev Notes

### Vite plugin para imagens
- Usar `vite-plugin-image-optimizer` ou `sharp` no build
- Converter imagens para WebP com fallback JPEG
- Gerar multiplos tamanhos:
  - Thumbnail: 300w (para listagem)
  - Medium: 600w (para lightbox mobile)
  - Full: 1200w (para lightbox desktop)
- Qualidade: 80 para WebP, 85 para JPEG fallback

### Lazy loading com LQIP
- Gerar placeholder blur (Low Quality Image Placeholder) para cada imagem
- Inline como data-uri base64 (tiny ~20x20px blurred)
- Enquanto imagem real carrega, mostrar blur placeholder
- Transition suave de blur para imagem real

### Responsive images
- Usar `<img srcset>` com breakpoints
- `sizes` attribute para indicar tamanho renderizado

### Admin: compressao no upload
- O admin ja usa sharp para processar imagens
- Verificar que qualidade/tamanho estao adequados
- Adicionar WebP output se nao existente

## Files affected

- `vite.config.ts` ou `app.config.ts` — plugin de otimizacao
- `src/components/card-tile.tsx` — srcset + LQIP placeholder
- `src/routes/colecoes.$slug.tsx` — srcset na galeria
- `admin/src/lib/image-processor.ts` — verificar output WebP

## Acceptance criteria

- [ ] Imagens servidas em WebP (com fallback)
- [ ] Multiplos tamanhos gerados automaticamente
- [ ] Placeholder blur visivel durante carregamento
- [ ] Lighthouse Performance score >= 90
- [ ] Build nao quebra com as otimizacoes

## Testing

- Throttle para 3G e verificar que blur placeholder aparece
- Rodar Lighthouse e conferir score de performance
- Verificar que imagens no admin continuam sendo processadas
