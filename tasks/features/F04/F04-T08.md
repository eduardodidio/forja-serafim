## User Story

As the developer, I want the Render deployment to work from the new repo
with the new service names so the site goes live under the new identity.

## Dev Notes

### Steps

1. **Verify `render.yaml`** is correct (done in T03):
   - Static site: `forja-serafim`
   - Admin: `forja-serafim-admin`

2. **Update Render dashboard** (manual — document steps):
   - Option A: Create new services from the `forja-serafim` repo
   - Option B: Update existing services to point to new repo
   - Either way, update env vars:
     - `GOOGLE_CLIENT_ID` — same value
     - `ALLOWED_EMAILS` — same value
     - `GITHUB_TOKEN` — new PAT if needed (new repo)
     - `RENDER_DEPLOY_HOOK` — will get new URL after service creation

3. **Update Google OAuth** (manual — document steps):
   - Authorized JS origins: update URL if domain changes
   - If service name changes, Render URL changes too:
     `https://forja-serafim-admin.onrender.com`

4. **Document DNS/domain plan** (if applicable):
   - If a custom domain is planned (e.g. forjaserafim.com.br), note it
   - For now, Render provides `forja-serafim.onrender.com`

5. **Create ADR** for the migration decision:
   - `docs/adr/0002-rebrand-forja-serafim.md`
