# F18-T04 — Verificacao E2E e Deploy Checklist

**Wave:** 3
**Status:** planned
**Type:** verification (manual + automated)

## User Story

Como desenvolvedor, quero validar que o fluxo completo de tokens funciona
em producao (upload -> watermark -> git-persist -> redeploy -> tokens visiveis),
para garantir que o problema do Castlevania nao se repete.

## Dev Notes

### Checklist de verificacao

1. **Pre-deploy**
   - [ ] `bun run build` passa sem erros
   - [ ] `bun run lint` passa sem erros
   - [ ] `collections.json` tem campo `tokens` em todas as colecoes

2. **Deploy no Render**
   - [ ] Push para main dispara deploy do static site
   - [ ] Admin service reinicia sem erros nos logs
   - [ ] Verificar nos logs do Render: `[startup]` messages ok

3. **Teste de tokens no admin**
   - [ ] Acessar admin, abrir colecao Castlevania
   - [ ] Upload de 1 token de teste (imagem + nome + quantidade)
   - [ ] Verificar nos logs do Render: `[git-persist] START`, `COMMITTED`, `PUSH OK`
   - [ ] Verificar no GitHub: commit `Auto-save: Upload tokens: castlevania` aparece
   - [ ] Verificar `collections.json` no GitHub: tokens array nao vazio
   - [ ] Verificar `public/images/tokens/castlevania/` no GitHub: imagem presente

4. **Teste de resiliencia**
   - [ ] Verificar `/api/persist-status`: state = "clean", recent mostra ultima op
   - [ ] Se falhar: verificar log detalhado, checar GITHUB_TOKEN no Render env vars

5. **Re-upload dos tokens do Anderson**
   - [ ] Avisar Anderson para re-fazer upload dos tokens do Castlevania
   - [ ] Confirmar que commit aparece no GitHub

### Arquivos a verificar
