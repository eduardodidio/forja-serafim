# F13-T03: Add /api/persist-status endpoint + state tracking

**Wave:** 1
**Status:** planned
**Depends on:** F13-T01

## User Story

As the admin UI, I need an API endpoint to check whether changes have been persisted to git, so I can show the correct banner state to the user.

## Dev Notes

### File: `admin/src/server.ts`

Add a new GET endpoint before the publish route:

```typescript
// --- Persist status ---
if (path === "/api/persist-status" && method === "GET") {
  return json({
    state: getPersistState(),   // "clean" | "dirty" | "pushing" | "error"
    error: getLastError(),       // null or error string
  }, 200, req);
}
```

Import `getPersistState` and `getLastError` from `./lib/git-persist.js`.

### Behavior:

| State | Meaning |
|-------|---------|
| `clean` | All changes committed and pushed to git |
| `dirty` | Changes written to disk, git operation queued/in-progress |
| `pushing` | Commit done, push in progress |
| `error` | Push failed — changes committed locally but not on GitHub |

### Additional: Add retry endpoint

```typescript
if (path === "/api/persist-retry" && method === "POST") {
  // Re-attempt push of already-committed changes
  gitPersist("Retry: re-push pending changes");
  return json({ state: getPersistState() }, 200, req);
}
```

This satisfies Saruman condition #2: push failures must have a retry option.

## Testing

- [ ] `POST /api/persist-retry` triggers a new push attempt
- [ ] Error state includes descriptive error message
