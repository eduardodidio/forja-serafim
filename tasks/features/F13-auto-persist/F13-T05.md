# F13-T05: Refactor publish to reuse gitPersist (deduplicate)

**Wave:** 2
**Status:** planned
**Depends on:** F13-T01, F13-T02

## User Story

As a developer, I want the publish endpoint to reuse the gitPersist helper instead of duplicating git add/commit/push logic, so the codebase is simpler and consistent.

## Dev Notes

### File: `admin/src/server.ts`

#### Current publish flow (lines 604-740):
1. `bun run build`
2. `git add` data files, covers, decks, manuals
3. `git diff --cached` + `git commit`
4. Handle detached HEAD
5. `git push` with GITHUB_TOKEN
6. Trigger Render deploy hook

#### New publish flow:
1. `bun run build` (unchanged)
2. `await gitPersist("Publicar site")` — this handles steps 2-5
3. Trigger Render deploy hook (unchanged)

#### Changes:

```typescript
if (path === "/api/publish" && method === "POST") {
  const steps: string[] = [];
  try {
    // 1. Build
    steps.push("Compilando site...");
    execSync("bun run build", { ...opts, stdio: "pipe" });
    steps.push("Build concluido.");

    // 2. Persist to git (reuse gitPersist, but AWAIT it here)
    steps.push("Salvando no git...");
    const result = await gitPersist("Publicar site");
    if (result.committed) {
      steps.push("Alteracoes salvas no git.");
    } else {
      steps.push("Dados ja estavam salvos.");
    }
    if (result.pushed) {
      steps.push("Enviado para o GitHub.");
    } else if (result.error) {
      steps.push(`Erro ao enviar: ${result.error}`);
      return json({ success: false, steps }, 500, req);
    } else {
      steps.push("Codigo ja estava no GitHub.");
    }

    // 3. Trigger Render deploy hook (unchanged)
    // ... keep existing deploy hook logic ...

    return json({ success: true, steps }, 200, req);
  } catch (err) { /* ... */ }
}
```

#### Important:
- Publish **awaits** gitPersist (unlike mutation endpoints which fire-and-forget)
- This is because publish needs to confirm push before triggering deploy hook
- Remove the duplicated git add/commit/push logic from publish (lines 616-700)
- Keep the build step and deploy hook step as-is
