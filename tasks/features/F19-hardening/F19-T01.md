# F19-T01 — Fix fetchAndRebase conflict detection + backup

**Wave:** 0
**Status:** done

## User Story

As the admin server, I want fetchAndRebase to detect merge conflicts in JSON files and restore from backup, so that corrupted data never reaches disk after a failed merge.

## Dev Notes

**File:** `admin/src/lib/git-persist.ts`

### Changes to `fetchAndRebase()` (lines 174-193)

1. **Before any git merge/pull**, create backup copies of all JSON data files:
   - `src/data/collections.json` -> `src/data/collections.json.bak`
   - `src/data/testimonials.json` -> `src/data/testimonials.json.bak`
   - `src/data/settings.json` -> `src/data/settings.json.bak`
   - Use `copyFileSync` from `fs`. Import the JSON paths from `paths.ts`.

2. **After `git pull --no-rebase`**, check for conflict markers in all JSON files:

   ```ts
   function hasConflictMarkers(filePath: string): boolean {
     try {
       const content = readFileSync(filePath, "utf-8");
       return content.includes("<<<<<<<") || content.includes(">>>>>>>");
     } catch {
       return false;
     }
   }
   ```

3. **If conflict markers detected**, restore from `.bak` files and log:

   ```ts
   log("ERROR", "CONFLICT detected post-merge, restoring backups");
   copyFileSync(`${path}.bak`, path);
   ```

4. **After successful merge (no conflicts)**, attempt `JSON.parse` on each file. If parse fails, also restore from backup.

5. **Clean up `.bak` files** at the end of `fetchAndRebase()` in a `finally` block (best-effort `unlinkSync`).

6. **Do NOT silently swallow errors** in the outer catch (line 190). Log the error:
   ```ts
   } catch (err) {
     log("ERROR", "fetchAndRebase failed", extractErrorDetail(err));
   }
   ```

### New exports needed by T05

Export `hasConflictMarkers` so server startup can use it.

## Acceptance Criteria

- [ ] Backup files are cleaned up after fetchAndRebase completes
- [ ] Outer catch logs the error instead of silently swallowing
- [ ] `hasConflictMarkers` is exported for use by other modules
