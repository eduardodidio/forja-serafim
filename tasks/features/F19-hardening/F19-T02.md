# F19-T02 — Add JSON validation to readJson/writeJson

**Wave:** 0
**Status:** done

## User Story

As the admin server, I want readJson to validate JSON integrity and detect conflict markers, so that corrupted files are caught immediately with actionable error messages instead of opaque crashes.

## Dev Notes

**File:** `admin/src/lib/data-io.ts`

### Changes to `readJson<T>(path)`

Wrap `JSON.parse` in a try/catch. Before parsing, check for conflict markers. On any error, throw a descriptive `DataCorruptionError`:

```ts
export class DataCorruptionError extends Error {
  constructor(
    public readonly filePath: string,
    public readonly reason: "conflict_markers" | "invalid_json" | "file_not_found",
    cause?: unknown,
  ) {
    super(`Data corruption in ${filePath}: ${reason}`);
    this.name = "DataCorruptionError";
    if (cause) this.cause = cause;
  }
}

export function readJson<T>(path: string): T {
  let raw: string;
  try {
    raw = readFileSync(path, "utf-8");
  } catch (err) {
    throw new DataCorruptionError(path, "file_not_found", err);
  }

  if (raw.includes("<<<<<<<") || raw.includes(">>>>>>>")) {
    throw new DataCorruptionError(path, "conflict_markers");
  }

  try {
    return JSON.parse(raw) as T;
  } catch (err) {
    throw new DataCorruptionError(path, "invalid_json", err);
  }
}
```

### Add `readJsonSafe<T>(path, fallback)`

Returns `fallback` on any error, logging the problem:

```ts
export function readJsonSafe<T>(path: string, fallback: T): T {
  try {
    return readJson<T>(path);
  } catch (err) {
    console.error(`[data-io] readJsonSafe fallback for ${path}:`, err instanceof Error ? err.message : err);
    return fallback;
  }
}
```

### Add `validateJson(path): boolean`

Returns true if file exists and parses as valid JSON with no conflict markers. Used by T05 startup self-heal.

```ts
export function validateJson(path: string): boolean {
  try {
    readJson(path);
    return true;
  } catch {
    return false;
  }
}
```

### Changes to `writeJson`

Add a `JSON.parse` round-trip validation after `JSON.stringify` to ensure we never write invalid JSON:

```ts
const jsonStr = JSON.stringify(data, null, 2) + "\n";
// Validate what we're about to write
JSON.parse(jsonStr);
writeFileSync(tmp, jsonStr, "utf-8");
```

## Acceptance Criteria

- [ ] `readJson` throws `DataCorruptionError` with reason `"conflict_markers"` when file contains git conflict markers
- [ ] `readJson` throws `DataCorruptionError` with reason `"invalid_json"` when file is not valid JSON
- [ ] `readJson` throws `DataCorruptionError` with reason `"file_not_found"` when file does not exist
- [ ] `readJsonSafe` returns fallback value on any error and logs the problem
- [ ] `validateJson` returns false for corrupted files, true for valid files
- [ ] `writeJson` validates JSON output before writing to disk
- [ ] `DataCorruptionError` is exported for use by server.ts
- [ ] TypeScript compiles without errors
