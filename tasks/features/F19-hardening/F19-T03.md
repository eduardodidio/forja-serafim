## User Story

As a developer, I want the vite build to succeed even when collections.json is malformed, so that a corrupted data file does not block deployments.

## Dev Notes

**File:** `vite.config.ts`

### Changes to `sitemapPlugin()` `closeBundle()` (lines 11-37)

Wrap the entire `closeBundle()` body in a try/catch. On error, log a warning and skip sitemap generation instead of crashing the build:

```ts
closeBundle() {
  try {
    const configDir = import.meta.dirname!;
    const collectionsPath = resolve(configDir, "src/data/collections.json");
    const raw = readFileSync(collectionsPath, "utf-8");

    // Check for conflict markers before parsing
    if (raw.includes("<<<<<<<") || raw.includes(">>>>>>>")) {
      console.warn("[sitemap] SKIPPED — collections.json contains merge conflict markers");
      return;
    }

    const collections = JSON.parse(raw) as Array<{ slug: string; hidden: boolean }>;
    // ... rest of sitemap generation (unchanged)
  } catch (err) {
    console.warn("[sitemap] SKIPPED — failed to generate sitemap:", err instanceof Error ? err.message : err);
  }
}
```

Key points:
- Do NOT import from admin code (vite.config.ts is in the frontend build context)
- Keep the conflict marker check inline (simple string includes)
- Log with `console.warn` not `console.error` since this is a non-fatal degradation
- The rest of the sitemap generation logic stays exactly the same

## Acceptance Criteria

- [ ] `bun run build` succeeds when `collections.json` contains conflict markers
- [ ] `bun run build` succeeds when `collections.json` is invalid JSON
- [ ] A warning is logged when sitemap generation is skipped
- [ ] `bun run build` still generates sitemap.xml when collections.json is valid
- [ ] No imports from admin code in vite.config.ts
