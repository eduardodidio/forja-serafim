# F19-T04 — Wrap API handlers with try/catch

**Wave:** 1
**Status:** done
**Depends on:** F19-T02

## User Story

As the admin panel user, I want API endpoints to return structured JSON error responses when data is corrupted, so that I see a helpful error message instead of a broken page.

## Dev Notes

**File:** `admin/src/server.ts`

### Strategy

Import `DataCorruptionError` from `data-io.ts`. Create a helper function that wraps the main `handleRequest` to catch unhandled errors:

```ts
import { readJson, readJsonSafe, DataCorruptionError } from "./lib/data-io.js";

async function safeHandleRequest(req: Request): Promise<Response> {
  try {
    return await handleRequest(req);
  } catch (err) {
    console.error("[server] Unhandled error:", err);

    if (err instanceof DataCorruptionError) {
      return json(
        {
          error: "Dados corrompidos. O servidor detectou um problema nos arquivos de dados.",
          detail: err.reason,
          file: err.filePath,
          recovery: "Reinicie o servidor para tentar auto-reparo, ou contate o desenvolvedor.",
        },
        503,
        req,
      );
    }

    const msg = err instanceof Error ? err.message : String(err);
    return json({ error: "Erro interno do servidor.", detail: msg }, 500, req);
  }
}
```

### Update `Bun.serve`

Change the `fetch` handler from `handleRequest` to `safeHandleRequest`:

```ts
Bun.serve({
  port: PORT,
  fetch: safeHandleRequest,
});
```

### Individual endpoint hardening (optional but recommended)

For the `GET /api/collections` endpoint specifically, since it is the most critical and most likely to fail on corrupted data, add an inline try/catch that returns a more specific message:

```ts
if (path === "/api/collections" && method === "GET") {
  try {
    const collections = readJson<Collection[]>(COLLECTIONS_JSON);
    // ... existing cache-bust logic
    return json(collections, 200, req);
  } catch (err) {
    console.error("[api] GET /api/collections failed:", err);
    return json(
      { error: "Falha ao carregar colecoes. Dados podem estar corrompidos.", detail: String(err) },
      503,
      req,
    );
  }
}
```

## Acceptance Criteria

- [ ] All API endpoints return JSON error responses (never crash/hang)
- [ ] `DataCorruptionError` returns 503 with `recovery` field
- [ ] Generic errors return 500 with `detail` field
- [ ] `Bun.serve` uses `safeHandleRequest` wrapper
- [ ] Error responses include CORS headers (via the `json()` helper with `req`)
- [ ] TypeScript compiles without errors
